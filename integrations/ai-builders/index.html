Why a prompt

Six rules generated payment code usually breaks

A tool that is only asked to add payments will tend to guess. Each prompt states these outright instead.

Amounts in major units

20.00 means twenty dollars. Tools used to Stripe send cents, and a checkout that multiplies by 100 charges a hundred times too much.

Keys stay on the server

The App ID, API key and webhook secret live in the platform's secret store, never in frontend code, a public variable, or the chat.

The signature is checked on the raw body

A webhook is trusted only after its HMAC verifies against the exact bytes received, inside a five minute window. A re-encoded body never matches.

The API has the last word

The webhook only says which payment changed. The order is updated from reading the payment back, never from the webhook body.

Safe to run twice

Retries and out-of-order delivery are normal. An order never moves backwards, and a repeated create cannot produce a second payment.

Paid means Captured

The return URL proves nothing. Fulfilment waits for the Captured state, and a declined card is read from the state, not from the HTTP status.
